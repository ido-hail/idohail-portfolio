# Portfolio Design Review

Review the portfolio as a professional engineering product, not as a
frontend showcase.

## Primary goals

The site should communicate one coherent professional identity:

Technical Operations & Engineering

Supporting areas:

- DevOps / Cloud / Platform
- Data Systems / DataOps / Automation
- Technical Leadership

The design must feel like a professional engineering portfolio rather
than a web-based resume.

## Review priorities

Evaluate, in this order:

1. Information hierarchy
2. Visual composition
3. Project prominence
4. Readability and line length
5. Whitespace and density
6. Responsive behavior
7. Consistency across routes
8. Accessibility implications

## Visual direction

Preserve:

- light, neutral visual foundation
- restrained slate palette
- one subtle blue accent
- strong typography and whitespace
- wider canvas for project-oriented content
- constrained prose widths
- minimal or zero client-side JavaScript

Avoid:

- card-heavy dashboard layouts
- SaaS/pricing-page aesthetics
- skill progress bars
- decorative terminal UI
- gradients without informational purpose
- decorative illustrations
- excessive animations
- frontend-demo gimmicks
- large keyword/logo walls

## Homepage

Review these as distinct visual content types:

- Hero
- Core Focus
- Selected Work
- Impact Snapshot
- Short About
- Closing Contact CTA

Do not recommend making every section use the same card or
heading-divider-paragraph pattern.

Selected Work should carry the strongest visual weight after the Hero.

## Project pages

Project indexes should degrade gracefully with project count.

Case-study pages should prioritize:

- clear h1
- concise metadata
- readable prose width
- clear h2 hierarchy
- architecture/screenshots where they add evidence
- decisions and tradeoffs over decoration

## Review behavior

Do not rewrite final portfolio copy unless explicitly asked.

Do not redesign sections merely because placeholder content looks sparse.

Separate findings into:

- must fix
- worthwhile refinement
- leave as-is

Prefer a small number of high-impact recommendations over subjective
micro-adjustments.
